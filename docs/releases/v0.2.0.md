# Nexus Panel v0.2.0

This release updates the single-container service workbench while retaining the existing SQLite account, session, group, service and event data. The database schema remains version 1.

## Changes

- Separate the service-gallery homepage from management routes. The homepage offers direct links, favorites, service details and an embedded read-only task schedule; management retains search, filtering, editing and explicit availability checks.
- Add read-only task snapshots and fixed CFSpeed/Quark-VOD integration adapters, with explicit unconfigured/demo states, source freshness and partial-coverage information. The panel does not run tasks or proxy business writes.
- Add four administrator-controlled homepage font presets: 柳体, 黑体, 宋体 and 楷体. The setting persists in `/data/nexus-settings.json` within the existing volume, independently of the account database. System-font appearance depends on the visitor's device.
- Support an optional login alias for an existing account and harden session expiry, origin validation, role checks, record IDs, imports, SSRF checks and asynchronous session boundaries.
- Align browser coverage with the current homepage and management routes, make audit build paths portable, include both Python test roots in CI, and include the bundled font's OFL license in source, runtime images and release bundles.
- Report the application version through `/api/health` in release images.

## Install or upgrade

Download `nexus-panel-v0.2.0-linux-amd64.tar.gz` and its `.sha256` file, verify the checksum and follow the [deployment guide](https://github.com/gnod-x/nexus-panel/blob/v0.2.0/docs/deployment.md). The bundle includes the Docker image and requires no source build.

For an existing installation, take a consistent private backup and retain the original Compose project, data volume, binding, origin, login alias, resource limits and read-only mounts. Change only the release image. A new setting file defaults to 柳体; no account reset or database import is required.

Keep the old image and backup until the upgraded installation is verified. Rolling back the application image leaves the new font preference file in place; older images ignore it. Restore database backups into an isolated empty volume before deliberately replacing any live data.

## Validation and boundaries

Release checks cover type checking, unit/API tests, both Python test roots, Chromium baseline behavior, independent Chromium/Firefox UI audits, and final-image clean-install/restart/backup-restore smoke tests. Exact run results and evidence limits are recorded in [testing](https://github.com/gnod-x/nexus-panel/blob/v0.2.0/docs/testing.md).

Task coverage remains partial. Missing/stale evidence never proves task success or absence. Synthetic fixtures do not establish household connectivity, sustained production capacity, device-specific font availability or successful execution of external jobs.
