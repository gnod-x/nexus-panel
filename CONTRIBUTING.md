# Contributing

1. Open an issue describing the user problem or proposed change.
2. Keep changes focused and add tests for behavior or security boundaries.
3. Run `npm run check` and the relevant Playwright tests.
4. Never include real service addresses, credentials, database files, or personal data in fixtures.
5. Describe any API or migration behavior change in `docs/api-contract.md` or `docs/migration.md`.

By submitting a contribution, you agree it is provided under the Apache-2.0 license in this repository.
